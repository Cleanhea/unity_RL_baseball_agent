# 1단계 모델에서 2단계로 넘어가는 타자 준비 과정

## 타이밍 집중·정타 진행 보상 강화 (2026-10-09)

Camera30 타자는 배트 위치·각도를 고정한 타이밍 과정부터 높이·각도·배트 위치를 차례로 열고 전체 준비로 연결한다. 몸 고정·30장·100Hz와 최종 정타·성적 통과 기준은 유지한다. 준비 과정 및 `batter_prepared=1`의 정타 미달 실제 페어 보상 상한을 0.5→1.5로 높이고 접촉 품질 75%·속도 25%로 진행 보상을 강화한다. [최신 계약·수식·실행](batter-timing-progress.md)을 따른다. 아래 약한 페어 0~0.5 기록은 변경 전 설명이며 준비 모드가 아닌 기존 학습에는 계속 적용한다.

## 타자 몸 위치 고정 (2026-10-09)

학습 타자의 몸 위치는 모든 과정에서 기준 위치로 고정한다. 기존 모델을 이어 쓰도록 행동 크기를 유지하며 몸 이동 행동 0·1만 무시한다. 배트 위치·스윙 각도·타이밍·30장 입력·성적 기준은 유지한다. [계약·학습 재개·검증](batter-fixed-stance.md)을 따른다. 아래 몸 이동 관련 기록은 변경 전 설명이다.

> 2026-10-08 후속 요청으로 현재 실행은 **6장·100Hz**다. 새 설정·모델 이식·실행/재개 명령은 [영상과 판단 간격 안내](batter-camera-timing.md)를 따른다. 아래3장 실행 명령은 이전 계약이며 현재 소스에서 직접 재개하지 않는다. 성적 기준과16개 준비 과정은 유지한다.

2026-10-08 사용자 요청으로 구현했다. 기존 2단계 동시 학습은 타자301,135·투수10,647스텝에 정상 저장하고 종료했다. 새 실행 `stage1_batter_camera_prepare`는 `stage1_batter_camera_power`의928,667스텝 체크포인트를 불러와 **타자만** 학습한다. 준비 통과 전에는 투수를 학습하지 않는다.

## 제어와 보상

관측은 기존 포수 카메라256×256 흑백3프레임·벡터16, 행동은 연속7·이산[2]다. 물리와 스윙 명령은 바꾸지 않는다.

- 준비 과정0의 제어 범위0.5·스윙 제한0.30초·투구 위치 분포(0.07,0.08)m는 저장된1단계 과정2와 같다. 모든 높이 행동도 기존 과정2와 같은 값을 만든다.
- 중립 배트 높이는 `0.5 * clamp(존 중심 높이 - PitchTarget 높이)`(기본−0.1225m)다. 제어 확대 중 고정하고, 최종 과정에서는 양쪽 합법 높이 끝값까지 도달한다.
- 기존 YAML은 기존 제어 의미를 유지한다. 준비 과정 또는 `batter_prepared=1`인 새 설정에서만 고정 중립 높이와 정타 보상을 사용한다. 준비 모델은 이 설정으로 이어받아야 한다.
- 실제 페어 타구의 품질≥0.6·속도≥120km/h·발사각5~35°면 정타 보상≥2.63, 약한 페어 타구는0~0.5다. 스윙 시도 보상과 접촉+1.5 보너스는 없다. 삼진·볼넷·파울과 원래 보상 정산 경계는 유지한다.
- `batter_preparation`과 `batter_prepared`는 새 타석 시작에만 적용한다.

## 과정과 성적 조건

| 과정 | 스윙 제한 | 제어 범위 | 투구 |
| --- | --- | --- | --- |
| 0~6 | 0.30→0.25→0.20→0.15→0.10→0.05→0초 | 0.5 | 기존 좁은 직구 분포,120~150km/h |
| 7~10 | 0초 | 0.625→0.75→0.875→1.0 | 같은 직구 분포 |
| 11 | 0초 | 1.0 | 위치 분포(0.15,0.17)m |
| 12 | 0초 | 1.0 | 위치 분포(0.25,0.28)m |
| 13~15 | 0초 | 1.0 | 기준5구종 분포를25→50→100% 섞음 |

11~15에서는 투구의25%를 존 중앙 직구로 유지한다. 나머지 구종·구속은 기존 프로필과 `BenchmarkPitcher` 분포다. 과정0은 완전 중앙 고정이 아니라 기존 체크포인트의 좁은 분포를 보존한다.

전용 Python 진입점은 설치된 ML-Agents 학습 루프·환경 파라미터 채널·통계 작성기를 사용한다. 외부 패키지는 수정하지 않는다. 보상이나 스텝 수만으로 전환하지 않는다.

구간마다 최소50개 완료 타석, 동일 과정의 연속3개 통과 구간, 과정별 최소30,000스텝이 필요하다. 혼합 과정·비유한 지표·표본 부족·실패 구간은 연속 통과 기록을 초기화한다.

| 과정 | 페어 접촉 타석 비율 | 정타 타석 비율 | 선구 조건 |
| --- | --- | --- | --- |
| 0~10 | ≥65% | ≥8% | 없음 |
| 11~12 | ≥40% | ≥5% | 존 스윙≥40%, 유인구 스윙≤35% |
| 13~15 | ≥30% | ≥5% | 존 스윙≥40%, 유인구 스윙≤35% |

이는 초기 실험 기준이다. 완료 타석마다 페어 접촉·정타를0/1 Histogram으로 기록해 표본 수를 보존한다. 볼넷·삼진은0이다. 스윙률은 공이 플레이트를 지나기 전에 시작한 시도 기준이며, 지나간 뒤 실제 스윙 타이밍 진단과 구분한다.

## 실행과 재개

독립 Unity 프로젝트에서 실행 파일을 빌드하며 원본 씬·GUID를 보존한다. 카메라에는 그래픽 장치가 필요하므로 `--no-graphics`를 사용하지 않는다. `-batchmode`는 그래픽 장치를 유지한다.

```powershell
cd C:\MainScreen\Dev\GitDirectory\unity_RL_baseball_agent
conda activate mlagents
python -u -B Training/prepare_batter.py Training/config/batter_preparation.yaml --run-id=stage1_batter_camera_prepare --results-dir=Training/results --env=Training/builds/BatterPreparation/BatterPreparation.exe --base-port=57341 --continue-stage2 --env-args -batchmode
```

`--continue-stage2`는 과정15가 성적 조건을 통과한 뒤 체크포인트·ONNX를 정상 저장하면 새 프로세스에서 `stage2_batter_pitcher_prepared_selfplay`를 실행한다. 준비 모델을 이어받아 타자·투수가 번갈아 학습한다. 기존 결과를 덮어쓰지 않는다. 준비가 최대2,000,000스텝에 도달하거나 중단돼도 기준 미달이면2단계로 넘어가지 않는다.

자동 연결은 실제 준비 실행의 체크포인트 경로를 전달하므로 준비 run-id나 결과 폴더를 바꿔도 다른 모델을 불러오지 않는다. 수동 연결에서 경로를 바꿨다면 `--prepared-checkpoint=절대경로`를 추가한다. 2단계 진입은 `batter_prepared=1`의 상수 설정도 검사한다. 준비 학습과 새 2단계 모두 `--no-graphics`와 기존 결과를 덮어쓰는 `--force`는 거부한다.

재개는 같은 명령에 `--resume`을 더한다. 스크립트가 초기 모델 경로를 해제해 해당 준비 실행의 체크포인트를 읽는다. `preparation-status.json` 이력을 실제 체크포인트 스텝에 맞추며 연속3개 구간을 다시 확인한다.

자동 연결을 쓰지 않았다면, 준비 통과 후 아래 명령으로2단계를 시작한다. `ready=true`, 최종 과정, 통과 구간 이후의 체크포인트를 확인한다.

```powershell
python -u -B Training/prepare_batter.py Training/config/stage2_batter_pitcher_prepared_selfplay.yaml --prepared-stage2 --run-id=stage2_batter_pitcher_prepared_selfplay --results-dir=Training/results --env=Training/builds/Stage2_PreparedSelfPlay/Stage2_PreparedSelfPlay.exe --base-port=57342 --env-args -batchmode
```

## 검증

`python -B Training/verify_preparation.py`는 실제 YAML·통계 타입·파라미터 관리자, 표본/정타/선구 조건, 혼합·NaN·볼넷/약한 타구의 전환 거부, 체크포인트에 맞춘 재개와 정상 저장 종료 경로를 검사한다.

Unity `Verify Open Training Scene`은 기존 실제 타격/보상/초기화와 저장된 제어 의미, 모든 과정의 중립 높이·합법 범위, 제한 해제,5구종·중앙 직구 분포, 새 타석 적용·통계 기록을 검사한다. 최종 준비 통과와 장시간 성능은 실제 학습 로그로 확인한다.

2026-10-08에는 C# 컴파일, Python 검사, 복제 프로젝트의 Unity 검사와 두 실행 파일 빌드를 통과하고 새 준비 학습을 시작했다. 첫3만 스텝 구간의317타석 중 페어 타구90.85%, 정타7.26%, 삼진9.15%, 평균 거리30.13m였다. 정타 기준8% 미달로 과정0을 유지한다. 최종 준비 완료·2단계 성능은 아직 검증하지 않았다. [상세 실행 기록](verification.md#1234-1단계-모델-보존과-2단계-진입-준비-과정-2026-10-08)을 참고한다.
