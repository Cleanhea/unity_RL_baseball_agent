# 중앙 직구 타자 제어와 평가

2026-09-18 사용자 요청으로 전체 플레이보다 **타자 우선 학습을 위한 네 항목의 제어·평가**를 우선한다. 현재는 학습기가 호출할 환경 명령과 진단 데이터를 구현했다. ML-Agents 패키지/Agent, Python trainer, 학습 실행, 보상 가중치는 아직 없다.

## 확인한 기존 문제와 변경

| 항목 | 기존 문제 | 현재 동작 |
| --- | --- | --- |
| 타자 위치 | 타자 Transform과 무관하게 손잡이가 투구 목표점에 고정 | 타자 위치를 바꾸면 손잡이와 전체 궤적도 이동 |
| 배트 위치 | 별도 위치 입력·평가 없음 | 타자 기준 손잡이의 X/Y/Z를 독립 조절 |
| 스윙 타이밍 | 스윙 중간 접촉만 허용하고 접촉 성공 때만 품질 제공 | 전체 스윙을 공간 검사하고 헛스윙에도 부호 있는 시간 오차 제공 |
| 스윙 각도 | 타구 출력 벡터만 바뀌고 배트는 같은 수평 궤적 | 좌우/상향각이 실제 스윙 평면을 회전시키며 접촉 순간 배트 진행 방향으로 타구 발사 |

## 과제 기준과 네 평가값

중앙 공을 맞히는 자세는 유일하지 않다. 몸과 손의 반대 이동이 같은 배트 궤적을 만들 수도 있다. 따라서 여기의 **위치 점수는 지정한 기준 자세에 대한 정확도**이며 모든 유효한 타격 자세의 우열이나 생체역학적 정답이 아니다. 접촉 여부·실제 타구 벡터와 함께 판단해야 한다.

기준 자세는 `BaseballEnvironmentConfig`에서 정한다. 타자는 `PitchTarget`의 지면점에서 X=-1.1m/Z=0m, 배트 중심 타점은 손잡이에서 길이의 80%, 기준 스윙은 좌우 0°/상향 15°다. 이 자세의 스윙 회전각 0°에서 중심 타점이 `PitchTarget`과 일치하도록 기준 손잡이 위치를 계산한다. 실제 손잡이는 **현재 타자 위치 + 기준 상대 손잡이 + 명령 오프셋**이므로 타자 이동을 자동으로 상쇄하지 않는다.

| 평가 | 원시 오차 | 0~1 점수 |
| --- | --- | --- |
| 타자 위치 | 기준 발 위치 대비 X/Z 오프셋 길이(m) | `Clamp01(1 - 오차 / StanceErrorScale)`; 기본 척도 0.5m |
| 배트 위치 | 기준 상대 손잡이 대비 X/Y/Z 오프셋 길이(m) | `Clamp01(1 - 오차 / GripErrorScale)`; 기본 척도 0.3m |
| 타이밍 | 스윙의 0° 자세 도달 시각 - 중앙 목표 예상 도달 시각(s) | `Clamp01(1 - abs(오차) / ContactHalfWindow)`; 기본 척도 0.05s |
| 스윙 각도 | 0° 자세에서 배트 진행 방향과 기준 스윙 방향 사이 각도(deg) | `Clamp01(1 - 오차 / SwingAngleErrorScale)`; 기본 척도 45° |

타이밍 음수는 빠름, 양수는 늦음이다. 스윙 0° 자세의 시각은 `시작 시각 + SwingDuration * Start / (Start - End)`이며 비대칭 스윙 범위에도 적용한다. 중앙 도달 시각은 발사 시 수평 거리/수평 속력으로 계산한다. 이는 현재 직구의 수평 등속 이동에 대한 기준이며 실제 충돌 시각 자체를 뜻하지 않는다. 입력 적용 해상도는 현재 Fixed Timestep 0.02초다.

스윙하지 않으면 타이밍/각도 점수는 0, `HasSwung=false`, `HasTimingReference=false`다. 원시 오차 0을 성공으로 해석하면 안 된다. 공-배트 최소 거리도 `HasClosestDistance`가 true일 때만 유효하다. `ContactTime=-1`은 미접촉이다.

타구 기본 속도는 기존 8–32m/s 사이에서 타이밍 품질 × 배트 중심 타점 근접도로 정한다. 2026-09-18 후속 요청으로 스윙 시작마다 UnityEngine.Random.Range(1.2f, 2f)로 파워 배율을 한 번 추첨하고 접촉 시 기본 속도에 곱한다(기존 대비 120~200%, 최상 품질 38.4~64m/s). 스윙 중에는 배율이 고정되고 R은 배율을 1로 초기화하지만 난수 상태는 되감지 않으므로 다음 스윙에서 새로 추첨한다. 네 평가 점수는 파워 배율에 영향받지 않는다. 재현 검증은 동일 난수 상태와 동일 스윙 호출 순서가 필요하다. 외야 경계 이탈은 현재도 홈런 판정 대신 OutOfPlay다. 방향은 접촉 당시 실제 배트 궤적의 접선이다. 타이밍 때문에 기준 방향에서 벗어난 타구가 나올 수 있으며 이 결과는 `ExitVelocity`로 확인한다. 타자·손잡이 위치 점수를 물리 속도에 곱하지 않는다. 네 점수의 합계나 RL 보상은 정의하지 않았다.

## 제어 API

수동 입력과 스크립트는 모두 `PlayDirector`를 호출한다. 실제 변경은 FixedUpdate에만 적용한다.

```csharp
director.SetManualInputEnabled(false); // 스크립트가 제어할 때 수동 입력 차단
director.RequestResetPlay();           // 다음 고정 단계까지 기다림

// Ready에서만 허용. 기준 자세로부터의 오프셋(m).
director.RequestBatterSetup(new BatterSetupCommand(
    new Vector2(0f, 0f),               // 타자 X/Z
    new Vector3(0f, 0f, 0f)));          // 상대 손잡이 X/Y/Z
director.RequestThrowPitch();          // 같은 틱이면 자세를 먼저 적용

// 원하는 투구 경과 시점에 한 번 요청. 예: 기본 투구에서 약 0.36~0.38초.
director.RequestSwing(new SwingCommand(0f, 15f)); // 실제 평면 좌우/상향각
BattingEvaluation result = director.GetBattingEvaluation();
```

스윙 명령의 기존 `SprayDegrees`/`LaunchDegrees` 이름은 호출 호환성을 위해 유지했지만 의미는 이제 **실제 스윙 평면의 좌우/상향각**이다. 타구 방향을 직접 지정하는 API가 아니다. 좌우 ±45°, 상향 -30~50°로 제한한다.

자세 선택은 투구 전 Ready에서만, 스윙은 PitchInFlight에서 한 번만 허용한다. 타자 X/Z는 각각 기준 ±0.75m, 손잡이 X/Y/Z는 각각 ±0.25/0.40/0.35m가 기본 한계이며 설정에서 변경한다. 범위를 넘거나 NaN/Infinity인 자세는 거부하고 이전 자세를 유지한다. 스윙 중 자세 순간이동으로 접촉하는 것을 막는다. 투구 중 연속 위치 제어와 실제 보행·팔 관절은 이번 구현에 없다.

`GetBattingEvaluation()`은 값 타입 스냅샷이다. 네 오차/점수(`Scores.x/y/z/w`), 몸/손잡이/배트 끝 위치, 접촉 여부, 검사된 최소 거리, 접촉 시각, 타구 속도를 제공한다. `BattingEvaluated` 이벤트는 접촉 순간 또는 미접촉 종료 시 한 번 발행한다. 평가 확정 후에도 타구 관찰은 계속되며 R은 자세·공·명령·평가 기록을 모두 초기화한다. 이벤트는 물리 진행 도중 발생하므로 처리기에서는 명령을 요청하고 직접 물리 상태를 바꾸지 않는다.

## 수동 확인

- 투구 전 **WASD**: 타자 X/Z 위치를 한 번 누를 때 5cm 이동.
- 투구 전 **IJKL**: 상대 손잡이 X/Z, **U/O**: 손잡이 높이 ±5cm.
- **방향키**: 스윙 평면 좌우/상향각. **P** 투구, **Space** 스윙, **R** 초기화.
- HUD의 네 오차/점수와 공-배트 최소 거리를 확인한다.
- Play Mode에서 타자를 선택하면 Gizmo가 손잡이, 스윙 궤적, 중심 타점 허용 반경을 표시한다.

설정 에셋의 스윙 시작/끝 각도 조절도 유지한다. 시작은 양수, 끝은 음수여야 중앙 접촉 자세 0°를 통과한다. 설정은 실행 전에 정하고, 배트 길이·평가 기준을 변경했다면 R로 초기화한다. 플레이 도중 설정 에셋 값을 바꾸는 것은 재현 검증 조건에서 제외한다.

## 검증과 다음 단계

`Tools > Baseball Simulation > Verify Batting Evaluation (Paused Play Mode)`에서 실제 Rigidbody 기반 검증을 반복할 수 있다. 기본 설정의 야구장 씬을 Play 후 Pause하고 실행한다. 테스트는 끝나면 Ready로 초기화하고 수동 입력/물리 모드를 복구한다. 결과와 제한은 `verification.md`의 12.4에 기록한다.

학습 연결 때는 위 명령과 스냅샷을 사용하는 ML-Agents 어댑터, 에피소드 초기 분포, 종료/보상 정책을 정해야 한다. 현재 초기 자세는 항상 기준 자세이고 투구도 고정이므로 위치 선택을 학습시키려면 초기 자세를 바꾸는 실험 조건이 추가로 필요하다. 이 환경 수정만으로 학습이 실행되거나 네 능력을 습득했다고 주장하지 않는다.
