# 현재 학습을 유지한 2→3단계 자동 연결

## 영상 30장·100Hz 적용 (2026-10-09)

현재 타자 영상 스택은 6→30장으로 변경했다. 256×256 흑백과 10ms 촬영/판단을 유지하며, 투구 중 연속 관측의 시간 범위는 290ms다. 기존 6장 모델의 1,062,459스텝 가중치를 별도 30장 초기화 모델로 옮기고, 전체 준비 과정 1에서 새 학습을 시작했다. Camera30 설정은 타자 배치 32·버퍼 256·궤적 64를 사용한다. 기존 6장 설정·실행 파일·학습 결과는 보존했다. [입력·모델 이식·메모리·실행 안내](batter-camera-30.md)를 따른다. 아래 6장 기록은 이전 검증 결과다.

2026-10-09 사용자 요청으로 기존6장 카메라 학습에 별도 `Training/continue_stage3.py` 대기 프로세스를 연결했다. 기존 Python 학습기·Unity Player·실행 인자·보상·모델은 수정하거나 재시작하지 않는다.

현재 자동 실행 순서는 다음과 같다.

1. `stage1_batter_camera6_skills`: 타이밍→높이→각도→위치10개 분리 과정.
2. `stage1_batter_camera6_skills_prepare`: 스윙 제한 해제·전체 제어·위치 확대·5구종의 기존16개 준비 과정. 각 성적 조건을 통과해야 한다.
3. `stage2_batter_pitcher_camera6_selfplay`: 준비 모델을 이어받아 타자·투수가 셀프플레이.
4. `stage3_full_team_camera6_selfplay`: 완료한2단계의 타자·투수 모델을 이어받고, 주자·중견수는 새로 학습.

첫 Python 프로세스는 기존 코드의 동기식 자식 실행을 통해 준비 과정과2단계 종료까지 살아 있다. 대기 프로세스가 그 정확한 프로세스의 종료를 기다리고, 종료 코드0과 아래 산출물 검증을 모두 확인한 뒤3단계를 시작한다. 새 스크립트는 기존 학습기에 신호를 보내거나 파라미터를 바꾸지 않는다. 대기 중에는10초마다 상태 파일의 시각을 갱신하며 GPU로 학습하지 않는다.

## 2→3단계 전환 조건

- 해당 체인의 전체 준비 상태가 `ready=true`·과정15이고, 준비 체크포인트가 마지막 통과 스텝 이상이어야 한다.
- 2단계가 종료하며 기록한 `configuration.yaml`의 run-id·결과 경로·타자 초기 모델이 이 체인과 일치해야 한다. 타자·투수의 self-play, 준비 모드, 네트워크와 학습 한도를 확인한다.
- 두 Behavior 모두 최종 `checkpoint.pt`와 결과 루트의 최종 ONNX가 존재해야 한다. 실제 저장 스텝은 타자≥12,000,000·투수≥260,000이어야 한다. 로그의 마지막 요약이나 파일 존재만으로 완료를 추정하지 않는다.
- 타자 actor·critic의 첫 시각 합성곱은6장 입력이어야 하고, 두 모델의 actor·critic 가중치는 유한해야 한다.
- 3단계 결과 폴더가 이미 있으면 덮어쓰지 않는다. 강제 덮어쓰기·구형3장 모델·기존 수비/주자 모델 초기화를 사용하지 않는다.

1단계 또는2단계를 중간에 멈추면 저장 파일이 있어도 위 조건에 미달하므로3단계는 시작하지 않고 대기 프로세스는 이유를 상태 파일에 기록한다. 전환은 학습 한도·저장 완료 기준이며,2단계의 높은 승률이나 실전 타격 성능을 보장하는 기준은 아니다.

## 3단계 설정

`Training/config/stage3_full_team_camera6_selfplay.yaml`은2단계 Camera6 타자·투수 설정을 이어 쓴다. 타자의100Hz 기준 할인율·GAE·시간 범위·요약·체크포인트·팀 교체 간격을 유지한다. `batter_prepared=1`로 학습한 높이 제어와 정타 보상을 유지하며1단계 준비 파라미터는 적용하지 않는다.

타자·투수만 self-play를 사용한다. 주자는 기존 POCA, 중견수는 설치된 `baseball_fielder_poca`를 사용하며 둘 다 새 모델로 시작한다. 수비 몸은 C·1B·2B·3B·CF 5명, 앞의4명은 고정·CF만 이동한다. CF는 포구 직후1·2·3루 중 하나로 송구한다. 씬과 센서/행동 계약은 기존 `Stage3_Camera6.exe`를 사용한다.

대기 프로세스는 검증한2단계의 실제 체크포인트 절대 경로를 `stage23_camera6_chain/stage3-resolved.yaml`에 작성한다. 이후 일반 ML-Agents 진입점인 `Training/train.py`를 그래픽이 켜진 배치 모드·별도 포트57364로 실행한다. 3단계 YAML의 기본 경로가 다른 과거 실행을 가리키더라도 실제 초기화에는 검증한 경로만 쓴다.3단계 종료 후에도 모든 Behavior의 저장 스텝/최종 모델을 확인해야 상태가 `complete`가 된다.

## 현재 실행·상태 확인

현재 작업에서 학습 체인 PID54608에 붙는 대기 프로세스를 이미 시작했다. 다음은 같은 작업을 새로 연결할 때 쓰는 명령이며, 이미 실행 중인 대기 프로세스를 중복 실행하지 않는다. PID는 실제 해당 체인의 루트 Python 프로세스로 바꾼다.

```powershell
cd C:\MainScreen\Dev\GitDirectory\unity_RL_baseball_agent
conda activate mlagents
python -u -B Training/continue_stage3.py --attach-chain-pid=54608
```

연결 대상은 같은 저장소와 결과 경로에서 `prepare_batter.py --skills --continue-stage2`로 실행한 해당 run-id의 프로세스여야 한다. 대기 스레드는 Windows 프로세스 핸들을 유지하는 단일 종료 대기를 사용한다.

```powershell
Get-Content -Encoding UTF8 Training/results/stage23_camera6_chain/continuation-status.json
```

상태는 `waiting_chain`→`validating_stage2`→`training_stage3`→`complete` 순서다. 조건 미달·학습 중단·오류는 `stopped`와 이유를 기록한다.3단계 학습 로그는 같은 폴더의 `stage3-training.log`다. 대기 프로세스가 실행 중인 동안 자동 연결이 유지된다. 대기 프로세스가 종료돼도 원래 학습은 독립적으로 계속 실행된다.

대기 중 자동3단계 연결만 취소하려면 다음 파일을 만든다. 기존 학습 체인을 중단하지 않는다.3단계 시작 후에는 이 파일로 학습기를 종료하지 않는다.

```powershell
New-Item Training/results/stage23_camera6_chain/stop-requested -ItemType File
```

준비 과정과2단계가 이미 끝난 뒤 연결하려면 `--attach-chain-pid` 대신 `--stage2-finished`를 사용한다. 같은 완료 검증을 수행한다. `continuation.lock`은 중복 대기를 막으며 정상 종료 시 제거된다. 강제 종료 후 남은 잠금은 파일에 기록된 PID와 생성 시각의 프로세스가 종료됐는지 확인한 뒤에만 제거한다. 중단 후 새 실행에서 같은 로그 파일이 이미 존재하면 별도 `--status-dir`을 사용해 기록을 보존한다.3단계가 이미 시작한 실행의 재개는 새 모델 초기화와 구분해 별도 resume 명령으로 수행한다.

## 검증 범위

`Training/verify_stage23.py`는 실제 설치된 ML-Agents/YAML/수비 등록 확장으로 설정을 파싱하고, 합성 저장 파일로 완료/중단/잘못된 경로/3장 모델/비유한 가중치/누락 모델/덮어쓰기 거부를 검증한다. 실제 CLI의 경로 재작성·학습 실행 명령·완료 확인과 대기 프로세스 종료/취소도 검증한다.

별도3단계 Player 점검에서는 현재의 부분 학습 타자와 기존 벡터 투수 가중치를 엄격하게 로드하고80개 Unity 통신 단계를 실행했다. 활성 타자·투수 관측/행동과 유한 출력을 확인했다. 이 점검은2단계 완료 모델을 사용한 학습 성능 평가가 아니며, 주자·수비는 타구가 발생해야 해당 통신 관측이 나타난다. 현재2단계 완료 전이므로 실제2→3 전환과3단계 장시간 학습은 아직 실행하지 않았다. [검증 기록](verification.md)을 따른다.
