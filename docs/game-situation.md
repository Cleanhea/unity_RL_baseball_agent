# 볼카운트·타석·주자 상황 (2026-09-26)

사용자 후속 요청으로 **볼카운트**, **주자 여러 명**, **타자 출루·아웃 결과 보상**을 추가했다. 규칙 계산은 ML-Agents와 Unity 물리에 의존하지 않는 `GameSituation`이 한다. `PlayDirector`는 투구 판정과 플레이 결과를 넘겨주고 결과의 단일 소유자로 남는다. 모든 씬에서 카운트를 세지만, 주자를 다음 타석으로 넘기는 것은 누상 주자 오브젝트가 있는 3단계 씬뿐이다.

## 볼카운트와 타석

| 투구 판정 | 카운트 | 타석 |
| --- | --- | --- |
| `Ball` | 볼 +1 | 4볼이면 **볼넷**. 타자 1루, 밀려나는 주자만 한 베이스, 만루면 1점 |
| `CalledStrike`·`SwingingStrike` | 스트라이크 +1 | 3스트라이크면 **삼진**. 아웃 +1 |
| `Foul` | 2스트라이크 전에만 +1 | 계속 |
| `InPlay` | — | **인플레이**로 끝난다. 아웃·득점·주자는 플레이 결과로 정한다 |

- 카운트는 `SetPitchCall`에서 투구 판정 이벤트보다 먼저 갱신된다. 그래서 이벤트 처리기는 새 카운트를 읽는다.
- 타석이 끝나면 다음 `RequestResetPlay`가 새 타석을 연다(카운트 초기화).
- 세 번째 아웃이 나오면 다음 타석에 새 반 이닝을 연다. 아웃·주자·반 이닝 득점을 지운다.
- `RequestNewPlateAppearance()`는 다음 초기화에서 카운트만 지운다.
- `RequestSetSituation(1루, 2루, 3루, 아웃)`은 Ready에서 새 상황을 정한다. 검증과 학습 상황 다양화에 쓴다.
- 조회: `GetSituation()`. 볼·스트라이크·아웃·주자·반 이닝 득점·타석 종료·결과를 준다.
- 디버그 화면 첫 줄에 `B/S/O`, 주자, 득점, 마지막 구종·구속이 나온다.

## 주자 여러 명 (3단계)

주자 슬롯은 네 개다. 0은 타자주자(`BatterRunner`), 1~3은 1·2·3루에서 타석을 시작하는 누상 주자(`BaseRunner_1B/2B/3B`)다. 새 타석마다 점유된 베이스에 해당 슬롯 주자를 세운다.

| 규칙 | 구현 |
| --- | --- |
| 포스 | 타자주자는 항상, 누상 주자는 뒤 베이스가 모두 차 있으면 포스다. 포스된 주자는 타구 순간 다음 베이스로 **자동으로 달린다**. 포스 베이스를 밟거나 뒤 주자가 아웃되면 포스가 풀린다 |
| 포스 아웃 | 공을 가진 수비수가 아직 도착하지 않은 포스 베이스 반경(0.6 m) 안에 있으면 아웃. 홈 포스 포함 |
| 태그 아웃 | 베이스를 벗어난(진루·귀루 중) 주자와 공을 가진 수비수가 0.8 m 안이면 아웃 |
| 뜬공과 리터치 | 뜬공을 잡으면 타자 아웃, 모든 포스가 풀린다. 시작 베이스를 벗어났던 누상 주자는 자동으로 돌아가 **리터치**해야 한다. 여러 베이스를 거꾸로 밟는다. 리터치 전에 공을 가진 수비수가 그 베이스를 밟으면 아웃(태그 아웃으로 기록). 리터치 뒤에는 진루(태그업)할 수 있다 |
| 플레이 종료 | 세 번째 아웃, 또는 살아 있는 주자가 없음(모두 득점·아웃), 또는 모든 살아 있는 주자가 베이스에 멈췄고 리터치할 주자가 없으며 수비가 공을 가졌을 때(`RunnerSafe`). 홈런·인정 2루타·파울·시간 초과는 기존 규칙이다 |
| 결과 반영 | 홈런은 모두 득점. 인정 2루타는 모든 주자 2베이스. 파울은 상황을 바꾸지 않는다. 그 밖에는 살아 있는 주자를 마지막으로 밟은 베이스에 둔다. 세 번째 아웃이 포스 아웃이거나 타자주자가 1루 전에 아웃되면 그 플레이의 득점은 인정하지 않는다 |

**넣지 않은 것**

- 주자 추월
- 한 베이스에 두 주자
- 도루·리드
- 실책
- 수비 방해

## 결과 요약과 보상

인플레이 플레이가 판정까지 끝나면 `PlaySummary`를 남긴다(`TryGetPlaySummary`, `PlayResolved` 이벤트).

| 항목 | 뜻 |
| --- | --- |
| `Outs` | 이 플레이의 아웃 |
| `Runs` | 인정 득점 |
| `BatterBases` | 타자가 안전하게 얻은 베이스(0~4) |
| `RunnerOuts` | 베이스 위 아웃. 타자 뜬공 아웃 제외 |
| `BasesAdvanced` | 살아남은 주자·타자주자가 전진한 베이스 합. 득점은 홈까지 |

1·2단계는 수비가 없어 판정 전에 초기화하므로 요약이 없다(`Resolved = false`).

| 대상 | 시점 | 보상 (`PlayOutcomeRewards`) |
| --- | --- | --- |
| 타자 | 타석 종료 | 볼넷 `+1`, 삼진 `-1`. 인플레이(판정됨)는 얻은 베이스마다 `+0.5`, 득점(타점)마다 `+0.5`, 그 플레이의 아웃마다 `-0.5`. 미판정 인플레이는 `0` |
| 투수 | 타석 종료 | 타자 결과 보상의 반대 부호 |
| 주자 그룹 | 인플레이 종료 | 전진 베이스마다 `+0.25`, 득점마다 `+1`, 베이스 위 아웃마다 `-1` |
| 수비 그룹 | 인플레이 종료 | 아웃마다 `+1`, 내준 베이스마다 `-0.25`, 득점마다 `-1`. 타구가 살아 있는 고정 단계마다 `-0.0005`. 수비 결정마다 포텐셜 기반 보조 보상([수비 보조 보상](fielding-agents.md#수비-보조-보상-2026-10-01)) |

예시는 다음과 같다(검증에서 확인한 값).

| 결과 | 타자 | 주자 그룹 | 수비 그룹 |
| --- | ---: | ---: | ---: |
| 주자 2루, 1타점 단타 (득점 1, 타자 1루) | `+1.0` | `+1.75` | `-1.75` |
| 병살 (아웃 2) | `-1.0` | `-2.0` | `+2.0` |

타자·투수의 투구 단위 보상은 그대로 투구마다 더한다. 에피소드 누적 보상은 투구 보상 합에 결과 보상을 더한 값이다. 투수 투구 보상은 카운트가 생겨 작게 다시 잡았다([투수 Agent](pitcher-agent.md)).

## 에피소드 경계 (`TrainingEnvController`)

- **타자·투수:** 한 **타석**이 한 에피소드다. 매 투구 `BeginPitch`, 타석이 끝나면 `EndPlateAppearance(결과 보상)`을 호출한다.
- **수비 그룹·주자 그룹:** 한 **인플레이 플레이**가 한 그룹 에피소드다. 주자 그룹에는 타구 순간 살아 있는 주자만 넣고, 플레이가 끝나면 뺀다.
- **무작위 상황:** 3단계는 새 타석의 `randomSituationProbability`(기본 0.3)만큼 누상 주자·아웃을 무작위로 정한다. 확률은 1루 0.5, 2루 0.4, 3루 0.3이고 아웃은 0~2다. 적용된 다음 고정 단계에 첫 결정을 요청해 관측에 반영한다.
- **중단:** 중단되면 모든 에피소드를 `Interrupted`로 닫고 새 타석을 요청한다.
