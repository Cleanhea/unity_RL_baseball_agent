# 타이밍 집중 학습과 정타 진행 보상 (2026-10-09)

사용자 요청으로 몸을 고정한 Camera30 타자에 기존 분리 준비 과정을 적용한다. 기존 전체 준비 실행은 정상 저장한 뒤 보존하고, 저장된 30장 가중치를 새 실행의 초기값으로 사용한다. 새 실행의 스텝은 0부터 센다.

## 학습 순서

`Training/config/batter_skills_camera30.yaml`과 `prepare_batter.py --skills --camera-stacks=30`을 사용한다. 첫 과정 `Timing`은 검증된 중앙 배트 위치·기준 각도를 고정하고 정책이 스윙 시점만 선택한다. 연속 7+이산 [2] 계약은 유지하며 공의 정답 위치·도착 시간을 정책 관측에 추가하지 않는다.

기존 10개 분리 과정: 타이밍 → 높이 25/50/100% → 각도 25/50/100% → 배트 X/Z 25/50/100%. 몸은 이후 과정과 2·3단계에서도 고정한다. 초기 투구는 존 중앙 포심 120~150km/h, 스윙 제한 0.30초다.

각 과정은 완료 타석 50개 이상, 페어율 ≥65%, 실제 정타율 ≥8%를 2만 스텝 요약에서 3회 연속 만족해야 한다. 과정별 최소 6만 스텝이다. 혼합 과정·실패·비유한 값은 연속 통과를 초기화한다. 보상 증가만으로 통과하지 않는다. 분리 준비 이후 기존 전체 준비 16개 과정을 실제 통과·저장해야 2단계로 간다. 3단계 대기 프로세스도 새 연결 실행을 추적한다.

공만 보이는 256×256 흑백 30장·벡터 16·100Hz와 물리·파워를 유지한다. 배치 32·버퍼 256·궤적 64로 영상 메모리를 제한한다.

## 진행 보상

준비 과정 및 `batter_prepared=1`에서만 강화한다. 실제 접촉과 유효 페어 판정이 있는 투구의 전체 보상을 한 번 정산한다. 파울·헛스윙·스윙 시도·기다리기에는 진행 보상을 주지 않는다. 기존 준비 모드가 꺼진 학습의 보상은 유지한다.

Q는 접촉 품질(타이밍 정확도 × 스위트스폿 정확도), v는 실제 초기 타구 속도(km/h), a는 실제 발사각이며 `clip01(x)=min(1,max(0,x))`다.

- 정타(Q≥0.6, v≥120, 5≤a≤35): 기존 `2 + 0.5×clip01(Q) + 0.5×clip01(v/180)` 유지(약 2.63~3).
- 정타 미달 페어: `(0.25 + 1.25×(0.75×clip01(Q/0.6) + 0.25×clip01(v/120))) × L(a)`.
- `L(a)=clip01(a/5)×clip01((50−a)/15)`. 5~35°는 1, 내려치기나 50° 이상은 0.
- 홈런: 기존 `0.5 + 3 + SpeedBonus(v/3.6)` 유지(3.5~4.5), 정타로 센다.

정타 미달 보상 상한은 0.5→1.5다. 품질에 75%, 속도에 25%를 두어 정타에 다가가는 실제 페어 타구의 차이를 강화한다. 정타 조건 하나라도 미달하면 정타 지표는 0이다. 기존 미접촉·파울·삼진·볼넷 및 타석 결과 정산은 유지한다. 가중치는 초기 실험값이며 수렴을 보장하지 않는다.

| 실제 페어 타구(각도 15°) | 진행 보상 |
| --- | ---: |
| Q=0.1, 60km/h | 0.5625 |
| Q=0.3, 60km/h | 0.875 |
| Q=0.3, 100km/h | 약 0.9792 |
| Q=0.6, 120km/h | 약 2.6333(정타) |

`LastPitchTrainingQualityReward`는 기존 기본 보상을 상쇄/보충하는 부호 있는 차액이다. 기본 접촉 보상과 중복 지급하지 않는다. 타석 보상은 이전 투구의 감점도 포함한다. 기존 품질·속도·발사각·페어율·정타율 통계로 실제 개선을 판단한다.

## 실행

```powershell
python -u -B Training/prepare_batter.py Training/config/batter_skills_camera30.yaml --skills --camera-stacks=30 --initial-checkpoint=Training/evaluations/timing_progress_20261009/checkpoint.pt --run-id=stage1_batter_camera30_timing --results-dir=Training/results --env=Training/builds/BatterCamera30/BatterCamera30.exe --base-port=57379 --continue-stage2 --env-args -batchmode -force-d3d11
```

재개는 같은 run-id에 `--resume`을 붙이고 `--initial-checkpoint`를 제거한다. 기존 결과를 덮어쓰는 `--force`는 사용하지 않는다. 실제 적용·저장 스텝·검증은 `Training/evaluations/timing_progress_20261009`와 [검증 기록](verification.md)에 기록한다. 구현 검증과 실제 학습 성능은 구분한다.
