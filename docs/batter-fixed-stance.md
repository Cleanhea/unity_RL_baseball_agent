# 타자 몸 위치 고정

2026-10-09 사용자 요청으로 학습 타자의 몸 위치를 기준 타격 위치에 고정한다. 매 투구 전 `BatterAgent`가 보내는 `BatterSetupCommand.StanceOffset`은 항상 `(0,0)`이다. 준비 과정 0~15, 분리 준비와 1·2·3단계에서 같은 규칙을 사용한다. 투구마다 몸 위치를 새로 뽑거나 이후 과정에서 몸 이동을 다시 열지 않는다.

기존 체크포인트를 이어 쓰도록 연속 행동 7개·이산 [2]를 유지한다. 연속 행동 0·1은 받되 몸 이동에는 사용하지 않는다. 배트 손잡이 위치 행동 2~4, 스윙 각도 행동 5~6, 스윙 타이밍과 과정별 제한은 유지한다. 영상 30장·256×256 흑백·10ms, 상태 벡터 16, 투구 분포·보상·통과 조건도 유지한다. 상태 벡터의 타자 위치 2개 값은 0이 된다. 수동 검증용 `RequestBatterSetup` API의 위치 조절 기능은 유지한다.

준비 과정 7~10의 제어 확대는 배트 위치·스윙 각도에 적용된다. 분리 준비의 위치 과정도 몸은 고정이며 기존 배트 손잡이 위치 조작을 사용한다. 몸 이동이 가능한 이전 실행의 성적은 고정 후 성적과 직접 비교하지 않는다.

## 적용과 검증

현재 학습은 92,652스텝·준비 과정 1에서 체크포인트/ONNX를 정상 저장했다. 원본 씬·GUID를 바꾸지 않고 복제 Unity 프로젝트에서 세 단계 검증과 Player 빌드를 통과했다. 기존 Player는 `Training/evaluations/fixed_stance_20261009/previous_builds/`에 보관한 뒤 새 Player로 교체하고, 같은 학습 결과 폴더에서 `--resume`으로 모델·optimizer·스텝을 이어 썼다. 재개 시 기존 연속 통과 기록을 초기화하므로 이동 가능한 몸으로 얻은 성적으로 다음 과정에 진입하지 않는다.

`TrainingStageVerification`은 세 단계에서 준비 과정 0~15와 양쪽 극단 이동 행동을 넣어 실제 타자 Transform/몸 오프셋이 고정되고 배트 조작은 살아 있는지 검사한다. 기존 실제 타격·주루·수비·초기화 검증도 수행한다. `Training/probe_fixed_stance.py`는 새 실제 Player에서 이동 행동 ±1을 보내고, 관측 위치 두 값의 0 유지·배트 위치 반응·30장 모델의 엄격한 로드와 유한 추론·원래 체크포인트의 불변을 확인한다.

실제 Player에서 230회 통신 단계·896개 관측·16회 자세 설정을 확인했다. 이동 행동을 양쪽 극단으로 주어도 타자 위치 관측 두 값은 모두 0이었고 배트 위치는 설정한 방향으로 바뀌었다. 기존 모델의 유한 추론 5회와 체크포인트 SHA256 불변도 확인했다. 학습 없이 위치·입력 호환성을 검사한 것이며 고정 후 타격 성능 평가는 아니다.

검증 산출물과 저장 지점은 `Training/evaluations/fixed_stance_20261009/`에 있다. 실제 실행 결과는 [검증 기록](verification.md)을 따른다. 현재 PID·로그는 `Training/evaluations/camera30_20261009/session.json`과 이 작업의 `session.json`에 함께 기록했다. 고정 후 장시간 타격 성능 개선은 아직 확인하지 않았다.
