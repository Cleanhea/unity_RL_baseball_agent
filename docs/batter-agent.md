# 타자 ML-Agents 연결

## 타자 카메라 192×192·12장 (2026-10-09)

사용자 요청으로 현재 학습 씬의 타자 카메라를 **192×192 흑백·12장·100Hz**로 변경한다. 최근 영상 범위는110ms이며 기존256×256·30장 대비 영상 원소 수가77.5% 줄어든다. 기존30장 학습은 정상 저장했고, 새 입력에 맞춘 타자 가중치와 기존 투수·주자·CF 가중치를 별도 초기값으로 보존한다. 타자 이식은 근사 초기화이므로 기존 타격 성능을 그대로 보장하지 않는다. 새 run-id와 새 Player를 사용한다. 현재 계약·실행·검증은 [타자 Camera12_192](batter-camera12-192.md)를 따른다. 아래30장·6장 기록은 이전 설정이다.

## 영상 프레임 재사용·수동 3단계 직행 (2026-10-09)

사용자 요청으로 30장·해상도·픽셀 값을 유지한 PNG 프레임 캐시와 흑백 배열 변환 최적화를 적용한다. 기존 타자 모델을 별도 보존해 준비·2단계를 생략하고 수동 명령으로3단계에 직접 사용할 수 있다. 투수·주자·CF는 새로 학습하며 기존 성적 통과로 간주하지 않는다. 기존 자동 연결은 취소했다. [계약·검증·첫 실행/재개 명령](batter-visual-cache-stage3.md)을 따른다.

## 타이밍 집중·정타 진행 보상 강화 (2026-10-09)

Camera30 타자는 배트 위치·각도를 고정한 타이밍 과정부터 높이·각도·배트 위치를 차례로 열고 전체 준비로 연결한다. 몸 고정·30장·100Hz와 최종 정타·성적 통과 기준은 유지한다. 준비 과정 및 `batter_prepared=1`의 정타 미달 실제 페어 보상 상한을 0.5→1.5로 높이고 접촉 품질 75%·속도 25%로 진행 보상을 강화한다. [최신 계약·수식·실행](batter-timing-progress.md)을 따른다. 아래 약한 페어 0~0.5 기록은 변경 전 설명이며 준비 모드가 아닌 기존 학습에는 계속 적용한다.

## 타자 몸 위치 고정 (2026-10-09)

학습 타자의 몸 위치는 모든 과정에서 기준 위치로 고정한다. 기존 모델을 이어 쓰도록 행동 크기를 유지하며 몸 이동 행동 0·1만 무시한다. 배트 위치·스윙 각도·타이밍·30장 입력·성적 기준은 유지한다. [계약·학습 재개·검증](batter-fixed-stance.md)을 따른다. 아래 몸 이동 관련 기록은 변경 전 설명이다.

## 영상 30장·100Hz 적용 (2026-10-09)

현재 타자 영상 스택은 6→30장으로 변경했다. 256×256 흑백과 10ms 촬영/판단을 유지하며, 투구 중 연속 관측의 시간 범위는 290ms다. 기존 6장 모델의 1,062,459스텝 가중치를 별도 30장 초기화 모델로 옮기고, 전체 준비 과정 1에서 새 학습을 시작했다. Camera30 설정은 타자 배치 32·버퍼 256·궤적 64를 사용한다. 기존 6장 설정·실행 파일·학습 결과는 보존했다. [입력·모델 이식·메모리·실행 안내](batter-camera-30.md)를 따른다. 아래 6장 기록은 이전 검증 결과다.

## 공만 렌더하는 센서 화면 (2026-10-09)

타자 관측 카메라는 검은 배경에 실제 공만 렌더한다. 일반 카메라·공 크기/물리·포수 시점·100Hz·벡터/행동 크기는 유지하며 별도로 진행된30장 변경을 보존한다. 기존 배경 포함 설명보다 이 계약이 우선한다. [적용·실행 파일·검증](batter-ball-only.md)을 따른다.

## 타이밍 분리 준비 (2026-10-09)

선택적 `batter_skill`은1단계 준비0에서만 적용한다. 처음에는 중앙 직구·고정 자세·기준 각도에서 스윙 시점만 제어하고 높이·각도·위치를 순차적으로 연다. 아직 열리지 않은 행동은 환경 명령에 적용하지 않는다. 기존 연속7+이산[2]·벡터16·카메라6장·100Hz와 정타 보상은 유지한다. 마지막 과정은 기존 준비0과 같은 행동 의미로 연결된다. [상세 계약](batter-skills.md)을 따른다.

## 영상 6장·촬영/판단 100Hz (2026-10-08)

사용자 요청으로 256×256 흑백 영상 스택을3→6장, 고정 물리·타자 촬영/판단 간격을20→10ms로 바꿨다. 과거 영상 범위는40→50ms이며 수비·주자 간격과 플레이 제한 시간은 기존 초 단위를 유지한다. 기존1단계 가중치를 동일 시점 채널에 이식한 별도 `stage1_batter_camera6_prepare` 실행을 사용한다. 아래3장/50Hz 설명은 이전 기록이다. [최신 계약·이식·실행·검증](batter-camera-timing.md)을 따른다.

## 2단계 타자 준비 과정 (2026-10-08)

준비 모드는 마지막1단계 과정2의 행동 의미를 보존하고 스윙 제한·제어 범위를 점진적으로 바꾼다. 중립 배트 높이는 고정하고 양쪽 합법 끝값에 도달한다. 준비 모델의2단계는 batter_prepared=1 모드를 사용한다. 관측·행동 크기는 같다. [계약·실행·검증](batter-preparation.md)을 따른다.

2026-09-24 요청으로 `BatterAgent`를 학습 입력원으로 연결했다. 에피소드는 **한 타석**이다([상황 규칙](game-situation.md)). Unity 6000.5.2f1과 ML-Agents 4.0.3을 사용한다. 2026-10-07 요청으로 공 관측을 머리 레이에서 **포수 시점 카메라 `CatcherEye`**로 바꿨다. 타자 자신의 상태·볼카운트·아웃·주자 벡터 16값은 유지하며 공의 정답 위치·속도는 넣지 않는다. 행동·보상도 유지한다. 관측 형태가 달라 **이전 레이 타자 체크포인트/ONNX와 호환되지 않는다.** 카메라 계약으로 1단계부터 새로 학습한다.

## 씬 연결

2026-09-26부터 타자 Agent는 **학습 단계 씬**(`Scenes/Training/Stage1~3`)에만 있다. `BaseballPlayground`는 Agent가 없는 수동 조작·검증용 틀 씬이다. 단계 씬은 `Tools > Baseball Simulation > Training > Build Stage N Scene`으로 만든다([학습 단계](training-curriculum.md)).

단계 씬에서 `PlayDirector`가 참조하는 타자 루트(`Actors/Batter`, `BatterController`와 같은 오브젝트)에 `BatterAgent`와 `BehaviorParameters`를 둔다.

- **배치 이유:** 같은 날 별도 `Systems/BatterAgent`에서 옮겼다. `Use Child Sensors`는 Agent 오브젝트의 자식 센서만 모은다. 센서 컴포넌트는 Agent의 자식으로 수집하고, 실제 카메라는 Field 아래에 고정한다. 투수·수비·주자 Agent도 각 선수 루트에 둔다.
- **명령 경계:** 같은 오브젝트에 있어도 Agent는 `BatterController`를 직접 호출하지 않고 `PlayDirector` 명령만 사용한다.
- **Behavior Parameters:** `Behavior Name = BaseballBatter`, `Behavior Type = Default`, `Team Id = 0`, `Use Child Sensors = true`, `Vector Observation Size = 16`, `Stacked Vectors = 1`, 연속 행동 7개, 이산 행동 분기 `[2]`, `Max Step = 0`
- **결정 요청:** Decision Requester는 두지 않는다. 같은 씬의 `TrainingEnvController`가 필요한 때만 결정을 요청한다. 투구 전 자세 1번, 공이 날아오는 동안 스윙할 때까지 매 고정 단계다. 투구 요청·초기화·수동 입력 끄기도 컨트롤러가 한다.
- **평가 타석 (2026-09-27, 2·3단계):** 새 타석의 약 10%는 컨트롤러가 타자의 Behavior Type을 `InferenceOnly`로, Model을 `Models/BenchmarkBatter_Stage1_Camera.onnx`로 바꿔 둔다. 이 타석의 타자 데이터는 학습기로 가지 않는다. 앞 타석 에피소드가 닫힌 뒤 바꾸고 타석이 끝나면 되돌린다. 약 10%는 기준 스크립트 투수가 던지며 타자는 평소처럼 학습한다. [고정 상대 평가](training-curriculum.md#고정-상대-평가-2026-09-27) 참고.

`Tools > Baseball Simulation > Add Batter ML-Agent To Current Scene` 메뉴는 단계 씬 빌더가 쓰며, 직접 실행해도 된다. 동작은 다음과 같다.

- 이전 전용 오브젝트(Agent 컴포넌트만 있고 자식이 없는 경우)가 있으면 지우고 타자 루트에 다시 붙인다.
- 위 Behavior Parameters 값은 실행할 때마다 다시 맞춘다. 관측 크기가 다른 씬도 메뉴 한 번으로 현재 계약(16)이 된다. 남아 있는 Decision Requester는 지운다.
- 프로젝트 태그 `Ball`을 등록하고 저장하며, 공 오브젝트에 이 태그를 붙인다.
- 기존 `BallEye` 레이를 제거하고 `CatcherEye` 카메라 센서를 만든다. 이미 카메라 센서가 있으면 Inspector 값을 보존한다.
- 저장된 단계 씬에는 `Training > Update Batter Camera Sensors In Current Scene`으로 모든 경기장의 센서만 전환할 수 있다. 이전 레이 정책 Model 참조와 고정 타자 모델 참조도 갱신한다.
- `Build Playground Scene`으로 틀 씬을 다시 만든 뒤에는 단계 씬 메뉴를 다시 실행한다. 공 태그도 그때 다시 붙는다.

## 포수 시점 카메라 `CatcherEye` (2026-10-07)

`Actors/Batter/CatcherEye`의 `CameraSensorComponent`가 `Field/BatterCatcherCamera`를 참조한다. 카메라는 홈 기준 `(0, 0.85, -1.2)` m에서 규칙 존 중심을 바라본다. 3단계 포수 몸 앞의 낮은 시점이며 타자 자세·스윙·주루로 움직이지 않는다. 각 경기장이 자기 Field의 카메라를 사용한다.

| 설정 | 기본값 |
| --- | --- |
| 영상 | 256×256 흑백 |
| 관측 스택 | 3 (영상 관측 shape `[3, 256, 256]` (CHW)) |
| 전송 압축 | PNG |
| 수직 시야각 | 50° |
| Near / Far | 0.05 / 180 m |
| 화면 렌더 | 카메라 disabled, 센서 결정 때만 오프스크린 렌더 |
| 후처리 / HDR / MSAA | 끔 |

카메라는 경기장의 실제 도형·배트·공을 렌더한다. 공 위치를 영상에 별도 표식으로 그리거나 정답 좌표로 제공하지 않는다. 3개 결정 프레임으로 이동을 추정하게 한다. 벡터 관측 스택은 별도로 1이다. **해상도·흑백 여부·스택은 학습 계약**이며 바꾸면 모든 단계와 모델을 함께 갱신해야 한다. 위치·FOV는 Inspector로 조절할 수 있지만 학습 뒤 변경하면 입력 분포도 달라진다.

멀리 있는 실제 크기 공은 몇 픽셀 이하이고, 타자·배트가 공을 가릴 수 있다. 가독성·학습 성능은 새 학습으로 확인해야 한다. 시각 입력은 그래픽 장치가 필요하므로 실행 파일 학습에 `--no-graphics`를 넣지 않는다. CNN은 `vis_encode_type: simple`이며 타자 `batch_size=128`, `buffer_size=2048`로 영상 버퍼 메모리를 제한한다.

기존 고정 타자 모델은 레이 계약이므로 연결하지 않는다. 새 1단계 모델을 `Models/BenchmarkBatter_Stage1_Camera.onnx`로 가져온 뒤 2·3단계 씬의 센서 갱신 메뉴를 실행해 고정 타자 평가를 다시 연결한다. 모델이 없으면 고정 타자 평가는 비활성이고 기준 스크립트 투수 평가는 유지된다.

## 행동 7 + 1

전체 조작(2·3단계, 1단계 최종 난이도, 학습 파라미터 없는 수동 검증)의 매핑은 다음과 같다. 1단계 준비 난이도는 아래 커리큘럼의 범위 제한을 적용하며 행동 수는 그대로다.

연속 행동은 각각 `[-1, 1]`이고 비유한 값은 0으로 처리한다. **투구 전 첫 결정**에서 연속 0–1은 타자 자세 x/z, 2–4는 손잡이 x/y/z를 설정 범위에 곱해 `RequestBatterSetup`에 전달한다. 투구는 그다음 컨트롤러가 요청한다(1단계 스크립트 투수, 2단계부터 투수 Agent). 이후 자세 행동은 무시한다. **투구 중 결정**에서 이산 분기 0은 대기, 1은 스윙이다. 첫 1일 때만 연속 5를 좌우각 `[-45°,45°]`, 연속 6을 상향각 `[-30°,50°]`로 바꿔 `RequestSwing`에 전달한다. 스윙 후 행동은 무시한다. 손잡이 위치는 투구 중 조정할 수 없는 현재 환경 제약을 따른다.

컨트롤러는 매 투구 `PlayReset` 직후 `BatterAgent.BeginPitch()`를 호출하고, 이때 `BatterRewardTracker.BeginEpisode`로 그 투구의 보상 수집을 시작한다. 보상 증분은 `AddReward`에 바로 더한다.

타석이 끝나면(볼넷·삼진·인플레이) 컨트롤러가 `EndPlateAppearance(결과 보상)`을 호출한다. 결과 보상을 더한 뒤 `EndEpisode`로 닫는다. 결과 보상은 볼넷 `+1`, 삼진 `-1`이다. 판정까지 끝난 인플레이(3단계)는 얻은 베이스마다 `+0.5`, 타점마다 `+0.5`, 그 플레이의 아웃마다 `-0.5`다. 1·2단계 인플레이는 수비가 없어 `0`이다([상황 규칙](game-situation.md)).

중단되면 `AbortPlay()`로 `EpisodeInterrupted` 처리한다. 타석 동안 한 번도 결정하지 않았으면(검증용 시나리오 타구) 에피소드로 닫지 않는다. ML-Agents는 결정 없이 두 번 부른 `EndEpisode`를 무시하고 누적 보상을 이어 가기 때문이다. Agent는 초기화를 직접 요청하지 않는다. 학습기도 모델도 없으면 ML-Agents는 `Heuristic`을 호출한다. 2026-09-26부터 `Heuristic`은 모든 행동을 0으로 두는 **중립 행동**이다. 기준 자세로 서서 공을 보기만 하고 스윙하지 않는다. 존 중앙 공 3개면 삼진으로 에피소드가 끝난다(`3 × -1 - 1 = -4`). 이전의 "0.38초에 15° 스윙" 규칙은 제거했다. 기본 구현은 매 결정마다 경고를 남기므로 재정의는 남겨 둔다. 초기 실험은 [보상 설계](batter-reward-design.md)의 고정 투구·고정 파워 조건을 권장한다.

검증 메뉴는 학습 단계 씬에서 Play Mode를 일시정지한 뒤 `Tools > Baseball Simulation > Verify Batter ML-Agent (Paused Play Mode)`다. 확인 항목은 세 가지다.

- 중립 휴리스틱으로 2개 에피소드가 스윙 없이 끝난다.
- 투구 비행 중 `CatcherEye`의 실제 영상에 공 픽셀이 나타난 결정 수를 보고한다.
- 손잡이를 존 중앙 높이로 낮추고 `OnActionReceived`에 스윙 행동을 직접 넣으면 명령 경계를 거쳐 공에 맞는다. 스윙 시점은 해석기가 계산한 도착 시각(`PlayDirector.PitchArrivalSeconds`)에서 스윙 중앙 위상만큼 앞이다. 이 시점과 자세는 검증 코드에만 있는 고정 입력이다. 실행 기록은 [검증](verification.md)에 둔다.

## 1단계 접촉 우선 커리큘럼 (2026-10-08)

첫 카메라 실행은 지켜보기 정책으로 굳어 접촉부터 배우도록 바꿨다. 후속 실행 `Training/resul/stage1_batter_camera_contact`는 마지막 287만 스텝 요약에서 접촉률 79.15%, 인플레이 타석 97.17%에 도달했지만, 타구 속도 60.80 km/h·발사각 −21.94°·첫 낙하거리 1.29 m였다. 계속 지급한 접촉 추가 보상 때문에 평균 타석 보상 +1.66으로도 약한 내려치기를 학습했다. 이에 접촉 다음에 정타를 배우는 과정을 추가했다. 카메라·벡터16·연속7·이산 `[2]` 계약은 유지한다.

| `batter_lesson` | 투구 위치 표준편차(좌우/높이) | 자세·손잡이·각도 | 스윙 선택 |
| --- | --- | --- | --- |
| 0 `CenterTiming` | 0 / 0 m, 규칙 존 중앙 | 타자 오프셋 0, 손잡이를 존 중앙 높이에 맞춤(기본 −0.245 m), 기준 스윙 각도 고정 | 투구 경과 0.30 s부터 자율 스윙 |
| 1 `SolidContact` | 0 / 0 m, 규칙 존 중앙 | 0과 같은 고정 자세·각도, 접촉 정확도를 먼저 개선 | 투구 경과 0.30 s부터 자율 스윙 |
| 2 `LimitedLocationAndPose` | 0.07 / 0.08 m | 기존 자세·손잡이 범위의 절반, 중앙 손잡이와 혼합; 기준 각도와 전체 행동 각도의 중간 | 투구 경과 0.30 s부터 자율 스윙 |
| 3 `FullBatting` | 기존 0.25 / 0.28 m | 기존 전체 제어 범위 | 기존 자율 스윙 |

분포는 기존 샘플러의 플레이트·존 경계 +0.25 m 제한을 사용한다. 네 과정 모두 포심 구속 120~150 km/h다. 0·1·2는 이산 action mask와 명령 경계에서 0.30 s 이전 스윙을 막는다. 대기는 항상 가능하고 자동 스윙·공 좌표 관측은 없다.

`TrainingEnvController`는 Academy 환경 파라미터를 **새 타석 시작 때** 읽어 고정한다. 파라미터가 없으면 −1로 기존 전체 조작·투구 분포·기본 보상을 사용한다. 2·3단계는 항상 −1이다. `SetBatterLessonOverride`는 격리 Editor 검증용이며 직렬화하지 않는다.

전환은 최소 타석 에피소드 100개와 스무딩한 보상 평균을 요구한다. 0→1은 >0.2, 1→2·2→3은 >1.0이다. `require_reset=false`이므로 경기장을 강제로 초기화하지 않는다. 접촉 추가 +1.5는 **0에서만** 지급하고 파울·유효 페어가 아닌 접촉은 완료 시 회수한다. 따라서 파울 순보상은 −1이다. 1·2·3에서는 실제 페어 타구의 접촉 품질 Q≥0.6, 속도≥120 km/h, 발사각 5~35°를 모두 만족하면 투구 보상 2.63~3, 그 밖의 페어 타구는 0~0.5다. 음의 발사각은 0이며 홈런은 기존 홈런 합계를 유지한다. [보상식](batter-reward-design.md#1단계-접촉-훈련-보상-2026-10-08)을 따른다. 이 기준은 훈련용 목표이며 실제 야구의 하드히트 분류와 다르다.

새 `stage1_batter_camera_power` 실행을 쓴다. 이전 세 과정의 상태 번호와 현재 네 과정은 달라 `--resume`하지 않는다. 자동 2단계 전환은 스텝 한도·최종 모델·최종 과정 3에 더해 최근 **전체 조작 요약 3개에서 정타 타석 비율 평균 ≥25%**를 요구한다. 볼넷·삼진·헛스윙도 이 비율의 분모에 포함된다. 1만 스텝 요약, 탐색 계수 `beta=0.02`는 유지한다.

`TrainingStageVerification`은 중앙 실제 접촉, 조기 스윙 차단, 정타 목표의 물리적 도달, 보상 합계, 파울 회수, 제한/전체 범위를 검사한다. Python 검사 `Training/verify_batter_curriculum.py`는 학습 설정·CNN·ONNX와 실제 TensorBoard 이벤트로 자동 전환을 검사한다. 장시간 새 학습의 성능은 아직 확인하지 않았다. [실행 안내](../Training/README.md)를 따른다.
