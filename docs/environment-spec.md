# 기본 야구 시뮬레이션 환경 명세

## 1. 문서 상태와 목표

이 문서는 **구현할 1차 환경의 요구사항**이다. 현재 프로젝트에서 이미 구현됐다는 뜻이 아니다. 2026-09-11 조사 시 야구 전용 객체와 동작은 없으며, 아래 기능은 모두 계획 상태다.

완료 목표는 학습 모델 없이 다음 한 플레이를 반복 실행하는 것이다.

1. 준비된 배치에서 직구를 던진다.
2. 타자가 수동 또는 스크립트 명령으로 스윙한다.
3. 접촉 여부와 타구 속도를 판정한다.
4. 타자주자 1명이 지정 경로로 이동한다.
5. 최소 수비 인원이 공을 포구하고 1루로 송구한다.
6. 결과를 하나로 확정해 표시한다.
7. 모든 상태를 초기 배치로 되돌리고 같은 절차를 다시 실행한다.

현재 목표는 야구 경기 전체가 아니라 독립된 한 플레이의 환경 동작 검증이다.

## 2. 좌표계와 야구장

### 2.1 좌표 기준

- 3D 공간에서 `1 Unity unit = 1 m`다.
- 홈 플레이트 지면 중심은 월드 좌표 `(0, 0, 0)`이다.
- `+Y`는 위쪽이다.
- `+Z`는 홈에서 투수판과 2루를 지나 중견수 쪽으로 향한다.
- `+X`는 홈에서 1루 쪽, `-X`는 3루 쪽이다.
- 투수와 야수의 기본 전방은 상황에 따라 홈 또는 공을 보게 하되, 좌표 기준 자체는 바꾸지 않는다.

이 기준에서 1·3루 파울선은 홈에서 각각 45도로 뻗는다. 간이 페어 영역의 지면 투영 조건은 `z >= abs(x)`이며 `z >= 0`이다.

### 2.2 주요 위치 기본값

아래 값은 구현 전 설계 기본값이며 Inspector 또는 설정 데이터에서 조절 가능해야 한다.

| 지점 | 월드 좌표(m) | 비고 |
| --- | --- | --- |
| 홈 | `(0, 0, 0)` | 모든 배치의 원점 |
| 1루 | `(19.40, 0, 19.40)` | 홈과 약 27.43 m |
| 2루 | `(0, 0, 38.79)` | 홈-2루 축 |
| 3루 | `(-19.40, 0, 19.40)` | 홈과 약 27.43 m |
| 투수 위치 | `(0, 0, 18.44)` | 투수판 지면 기준 |
| 투구 시작 | `(0, 1.80, 18.44)` | 손 위치의 단순 근사 |
| 투구 목표 | `(0, 1.00, 0.50)` | 홈 앞 스트라이크 존 근사 |

베이스 크기나 실제 구장 형태를 정밀 복원하는 것이 목적은 아니다. 베이스 간 거리는 익숙한 규모를 제공하는 기본값이고, 판정은 별도의 도착 반경을 사용한다.

### 2.3 필드 표현과 경계

- 지면, 내야, 외야, 파울 영역을 기본 Plane/Quad/Cube와 URP 호환 단색 머티리얼로 구분한다.
- 홈, 각 베이스, 투수 위치는 독립된 표식 객체로 둔다.
- 파울선은 선형 메시, 얇은 Cube 또는 디버그 선으로 표시한다.
- 기본 플레이 경계는 홈 기준 수평 반경 `110 m`, 상단 `Y = 60 m`, 하단 `Y = -2 m`다.
- 페어 외야 경계를 넘은 공은 홈런으로 판정하지 않고 `OutOfPlay`로 종료한다.
- 카메라는 홈 뒤쪽의 높은 3인칭 고정 시점을 기본으로 하되 공, 1루, 최소 수비 인원이 한 화면에 들어오게 조정한다.
- 기존 `SampleScene`의 Main Camera, Directional Light, Global Volume과 URP 설정은 재사용할 수 있다.
- Scene 뷰 Gizmo와 Game 뷰 디버그 표시로 원점, 축, 베이스 경로, 파울선, 공 속도 벡터, 포구·도착 반경을 확인할 수 있어야 한다.

## 3. 구성 객체와 역할

| 구성 객체 | 환경에서 맡는 역할 |
| --- | --- |
| Environment Root | 한 플레이 관련 객체와 설정의 상위 컨테이너 |
| Field / Boundary | 지면 충돌, 페어·파울 및 장외 영역 판정 |
| Home / Base Markers | 주루 경로와 베이스 도착·포스 판정 기준 |
| Pitch Origin / Target | 투구 시작 위치와 목표 위치 |
| Ball | Rigidbody 이동, 충돌, 위치·속도, 지면 접촉, 소유 상태 |
| Batter / Bat | 타자 표시, 스윙 진행, 접촉 구간 제공 |
| Runner | 타자주자 1명의 현재 위치, 목표 베이스, 도착 상태 |
| Ball Fielder | 타구 또는 단순 예상 낙하지점으로 이동해 공 처리 |
| First Baseman | 1루에서 송구를 받아 포스 아웃 조건 제공 |
| Play Director | 상태 전이, 시간, 사건 순서, 결과 확정, 초기화 총괄 |
| Manual Controller | 키보드 등 수동 입력을 공통 환경 명령으로 변환 |
| Scripted Controller | 정해진 시간·값의 검증 시나리오를 같은 명령으로 실행 |
| Debug View | 상태, 속도, 소유 선수, 결과, 타이머와 공간 보조선 표시 |

선수는 초기에는 Capsule, 공은 Sphere, 배트는 길쭉한 Capsule/Cylinder 등 기본 도형으로 표현한다.

## 4. 주요 설정 기본값

| 설정 | 기본값 | 목적과 근사 범위 |
| --- | --- | --- |
| 고정 시간 간격 | 프로젝트 기존값 `0.02 s` | Rigidbody와 이동 판정의 기준 |
| 중력 | 프로젝트 기존값 `(0, -9.81, 0)` | 공의 낙하 |
| 공 반지름 / 질량 | `0.037 m / 0.145 kg` | 크기와 Rigidbody 기본값 |
| 투구 속도 | `36 m/s` | 첫 직구 검증용 |
| 공 정지 기준 | `0.15 m/s` 미만이 `1.0 s` 지속 | 지면 접촉 뒤 정지 처리 |
| 한 플레이 제한 시간 | `12 s` | 교착 상태 방지 |
| 스윙 시간 | `0.25 s` | 시작부터 종료까지 |
| 유효 접촉 시간 폭 | 예상 중심 기준 `±0.05 s` | 타이밍 품질 계산 |
| 접촉 허용 반경 | 공 중심에서 `0.09 m` | 실제 공보다 넓힌 검증용 근사 |
| 배트 길이 | `1.0 m` | 기본 도형 표시와 접촉 궤적 |
| 타구 속도 범위 | `8–32 m/s` | 접촉 품질에 따른 단순 출력 |
| 좌우 타구 각 | `-45°–45°` | `+Z` 기준; 양수는 1루 쪽 |
| 발사각 | `0°–50°` | 땅볼부터 뜬공 검증 |
| 주자 속도 / 도착 반경 | `7 m/s / 0.30 m` | 경로 이동과 도착 판정 |
| 수비수 속도 | `6 m/s` | 단순 자동 이동 |
| 포구 반경 / 높이 | `1.0 m / 2.5 m 이하` | 손·글러브 애니메이션 없는 근사 |
| 송구 속도 / 수신 반경 | `25 m/s / 0.75 m` | 직선 송구와 소유권 이전 |

Rigidbody 공에는 빠른 이동 중 누락을 줄이기 위해 연속 충돌 검사를 사용한다. 접촉 허용 반경과 포구 반경은 실제 크기보다 큰 검증용 값이며, 실제 야구 정확도를 주장하지 않는다.

설정값은 하나의 환경 설정 데이터에 모으되, 단 한 곳에서만 쓰이는 표시 옵션까지 억지로 중앙화하지 않는다. 시나리오별 변경값과 난수 시드를 실행 시작 시 기록해 재현 조건을 알 수 있게 한다.

## 5. 기능 요구사항

### 5.1 공과 투구

- 초기화 시 공은 투구 시작 위치에 정지 상태로 배치되며 투수 소유 또는 투구 대기 상태다.
- `ThrowPitch` 명령은 `Ready` 상태에서만 허용한다.
- 첫 구현은 회전과 구종 효과가 없는 직구 하나다. 목표 방향으로 `투구 속도`의 초기 속도를 적용한 뒤 Unity 중력을 사용한다.
- 공은 매 고정 시간 단계에서 월드 위치, 선속도, 지면 접촉 여부, 경기 영역 여부, 소유자를 제공한다.
- 공이 소유 상태가 되면 자유 Rigidbody 이동을 멈추고 소유자의 수신 지점에 붙인다. 송구 시 소유권을 해제하고 새 속도를 적용한다.
- 공이 정지 기준을 만족한 뒤 지원되는 판정으로 진행할 수 없으면 `DeadBall`로 종료한다.
- 경계 이탈, 제한 시간, 비정상 하단 낙하는 종료 조건으로 처리한다.
- 변화구, 스핀, 공기 저항·마그누스 효과는 후속 확장이다.

### 5.2 타격

- `Swing` 명령은 스윙 시작 시각, 좌우 배트 각, 발사각을 전달한다.
- 타자는 수동 입력 또는 스크립트 명령으로 같은 스윙 동작을 실행한다.
- 배트 표시는 스윙 시간 동안 단순 회전한다. 정밀 애니메이션과 인체 관절은 요구하지 않는다.
- 접촉은 이전 배트 위치에서 현재 위치까지의 휩쓸린 구간과 공 사이 거리를 검사해 빠른 공의 터널링을 줄인다.
- 접촉 시 타이밍 오차, 배트 좌우 각, 발사각으로 타구 방향과 속도를 계산하고 공 Rigidbody 속도를 한 번 갱신한다.
- 타이밍 품질은 유효 접촉 시간 중심에서 멀수록 1에서 0으로 선형 감소한다. 타구 속도는 설정된 최소·최대 속도 사이에서 품질에 따라 보간한다.
- 좌우 방향은 `+Z`에서 배트 각만큼 회전하고, 수직 성분은 발사각으로 만든다. 필요하면 가장자리 접촉 품질을 추가 배율로만 낮춘다.

이 방식은 **접촉 검출에는 공간 검사, 접촉 결과에는 단순 계산을 쓰는 혼합 모델**이다. 원시 배트 Rigidbody 충격만 쓰는 방식보다 타이밍과 각도의 영향을 직접 조절하고 반복 검증하기 쉽다. 대신 배트 질량, 회전 관성, 공 변형, 스핀은 근사하지 않는다.

### 5.3 주루

- 유효 타격 직후 타자는 타자주자 상태로 전환한다.
- 경로 순서는 홈 → 1루 → 2루 → 3루 → 홈으로 고정한다.
- `SetRunnerTarget` 명령은 경로상 현재 위치보다 앞선 베이스 하나 또는 시나리오의 최종 목표를 지정한다.
- 주자는 베이스 사이 선분을 따라 고정 시간 단계에서 이동하고, 현재 위치·다음 베이스·최종 목표·도착 여부를 제공한다.
- 기본 판정 모드는 1루를 최종 목표로 하며 도착 시 `SafeAtFirst`로 종료한다.
- 득점 검증 모드는 최종 목표를 홈으로 설정하고 중간 베이스에서는 종료하지 않는다. 홈 도착 시 `RunScored`로 종료한다.
- 한 플레이에는 타자주자 1명만 존재한다.
- 리드, 도루, 귀루, 태그업, 슬라이딩, 복수 주자 경합은 후속 확장이다.

### 5.4 수비

- 최소 구성은 타구 처리 수비수 1명과 1루 수비수 1명이다.
- 타구 처리 수비수는 공의 현재 위치 또는 중력만 고려한 간이 낙하지점을 목표로 이동한다.
- 낙하지점 예측이 유효하지 않으면 공의 지면 투영 위치를 따라간다.
- 공이 포구 반경·높이 조건 안에 들어오면 포구를 시도한다. 첫 지면 접촉 전 포구는 `FlyOut`, 이후 포구는 소유권 획득으로 처리한다.
- 소유한 수비수는 지정 대상에게 `ThrowTo` 명령으로 직선 송구한다. 기본 자동 검증에서는 1루 수비수가 대상이다.
- 수신 반경 안에서 1루 수비수가 공을 받으면 소유권을 그 선수로 원자적으로 이전한다.
- 1루 수비수가 공을 소유하고 1루 도착 영역에 있는 상태가 주자 도착보다 먼저 성립하면 `ForceOutAtFirst`다.
- 자동 수비는 기능 검증용 규칙 기반 스크립트이며 학습 정책이 아니다.

### 5.5 조작과 디버그

- 공통 조작은 플레이 시작/투구, 스윙, 주자 목표 지정, 수비 이동 목표, 송구 대상 지정, 일시 정지/재개, 초기화다.
- 수동 모드와 스크립트 검증 모드는 동시에 명령을 내리지 않는다. 활성 입력 소스를 표시한다.
- Game 뷰에는 최소한 플레이 상태, 경과 시간, 공 속도, 공 소유자, 주자 목표/도착, 최종 결과를 표시한다.
- Scene 뷰에는 베이스 경로, 파울선, 경기 경계, 공 속도 벡터, 포구·수신·베이스 도착 반경을 켜고 끌 수 있게 한다.
- 주요 수치와 시나리오 시드는 Inspector 또는 설정 데이터에서 바꿀 수 있어야 한다.

## 6. 플레이 상태와 전이

| 상태 | 진입 조건 | 허용되는 핵심 동작 | 다음 상태 |
| --- | --- | --- | --- |
| `Ready` | 초기 배치 완료 | 투구, 설정 확인, 초기화 | `PitchInFlight` |
| `PitchInFlight` | 투구 명령 수락 | 스윙, 공 추적 | 접촉 시 `RunnerDefense`; 미타격 확정 시 `Ended` |
| `RunnerDefense` | 유효 배트 접촉 | 주루, 수비 이동, 포구, 송구 | 종료 판정 시 `Ended` |
| `Ended` | 결과 하나 확정 | 결과 표시, 초기화 요청 | `Resetting` |
| `Resetting` | 초기화 요청 | 입력 차단, 상태 복원 | 복원 완료 시 `Ready` |

일시 정지는 별도 경기 결과가 아니다. 시뮬레이션 시간과 명령 적용을 멈추고 같은 상태에서 재개한다. `Ended` 이후 들어온 플레이 명령은 무시하고 이유를 디버그 로그에 남긴다.

## 7. 환경 이벤트와 상태 조회

최소 이벤트는 `PitchThrown`, `SwingStarted`, `BallBatContact`, `PitchMissed`, `BallGrounded`, `BallCaught`, `ThrowStarted`, `BallPossessionChanged`, `BaseReached`, `OutRecorded`, `RunScored`, `BallOutOfPlay`, `PlayTimedOut`, `PlayReset`이다.

각 이벤트에는 시뮬레이션 시각, 고정 틱 번호, 관련 객체, 필요한 위치·속도, 시나리오 시드를 기록한다. 이 이벤트는 환경에서 일어난 사실이며 강화학습 보상값이 아니다.

상태 조회는 적어도 다음 정보를 한 시점의 읽기 전용 스냅샷으로 제공한다.

- 플레이 상태, 결과, 경과 시간, 시드
- 공 위치·속도·지면 접촉·소유자
- 선수 위치와 공 소유 여부
- 베이스 위치
- 주자 위치, 다음/최종 목표 베이스, 도착 상태

관측 벡터의 순서나 정규화, 행동 공간, 보상값은 후속 단계에서 별도로 정한다.

## 8. 지원 규칙과 단순화

| 항목 | 현재 지원 방식 |
| --- | --- |
| 투구 | 목표점을 향한 직구 1개; 볼/스트라이크 판정 없음 |
| 미타격 | 공이 홈 뒤 미타격 판정면을 통과하고 접촉이 없으면 `Miss`로 플레이 종료 |
| 파울 | 첫 지면 접촉 또는 경계 이탈 지점이 간이 페어 영역 밖이면 `Foul`; 카운트 없이 종료 |
| 뜬공 포구 | 첫 지면 접촉 전에 포구하면 `FlyOut`; 파울 뜬공도 포구가 먼저면 아웃 |
| 땅볼 처리 | 지면 접촉 뒤 포구·송구 가능 |
| 1루 포스 | 수비의 공 소유+1루 점유가 주자 도착보다 먼저면 `ForceOutAtFirst` |
| 1루 세이프 | 주자 도착이 1루 포스보다 먼저면 `SafeAtFirst` |
| 득점 | 득점 전용 시나리오에서 단일 주자가 순서대로 베이스를 지나 홈 도착 시 `RunScored` |
| 장외 | 페어 외야/상하 경계를 벗어나면 `OutOfPlay`; 홈런으로 보지 않음 |
| 정지 | 지원 판정 없이 공이 정지 조건을 만족하면 `DeadBall` |

삼진, 볼넷, 볼카운트, 태그 아웃, 병살, 희생플레이, 인필드 플라이, 에러, 홈런, 이닝과 팀 점수 운영은 지원하지 않는다. 한 플레이 결과값 이상의 정규 기록도 만들지 않는다.

## 9. 종료 판정 우선순위

사건은 발생한 시뮬레이션 시각과 고정 틱을 보존해 한 곳에서 결과를 하나만 확정한다. 서로 다른 틱이면 먼저 발생한 유효 사건이 우선한다. 같은 고정 틱에 충돌하면 다음 순서를 사용한다.

1. 필수 참조 손실이나 숫자 비정상 등 안전 중단 `InvalidState` — 야구 결과와 구분한다.
2. 첫 지면 접촉 전 포구 `FlyOut`
3. 1루 포스와 1루 도착 — 둘이 같은 틱이면 단순화 규칙으로 `ForceOutAtFirst` 우선
4. 득점 목표 시 홈 도착 `RunScored`
5. `Foul`, `Miss`, `OutOfPlay`, `DeadBall`
6. `Timeout`

이미 결과가 확정된 뒤의 이벤트는 로그 진단용으로만 남기고 결과를 바꾸지 않는다. 파울 지면 접촉과 포구가 같은 틱이면 첫 지면 접촉 여부의 이벤트 시각을 비교하고, 구분할 수 없을 때는 뜬공 포구를 우선한다. 이는 정식 야구 판정이 아니라 한 틱 안의 중복 결과를 막는 명시적 근사다.

## 10. 초기화 조건

초기화는 `Ended`에서뿐 아니라 디버그 중 언제든 요청할 수 있으며 다음 고정 시간 단계에서 한 번 수행한다.

1. 입력 수락을 중지하고 예약 명령·판정 이벤트를 비운다.
2. 공 소유권을 해제하고 Rigidbody 선속도·각속도를 0으로 만든다.
3. 공, 타자, 배트, 주자, 수비수를 기록된 초기 Transform으로 복원한다.
4. 스윙 진행도, 지면 접촉, 포구·송구, 주자 경로와 도착 플래그를 지운다.
5. 플레이 상태, 결과, 경과 시간, 이벤트 순번을 초기값으로 되돌린다.
6. 설정된 시드로 시나리오 난수원을 다시 만든다.
7. Transform과 물리 상태의 동기화가 끝난 뒤 `Ready`로 전환하고 `PlayReset`을 기록한다.

연속 초기화는 멱등적이어야 한다. 초기화 직후에는 공 속도 0, 소유자 없음 또는 투구 대기 소유자, 주자 비활성, 결과 없음, 타이머 0이어야 하며 이전 플레이 이벤트가 새 결과에 영향을 주면 안 된다.

## 11. 환경 제작 완료 기준

- 기본 도형만으로 홈·베이스·투수 위치·페어/파울·경계를 식별할 수 있다.
- 수동 모드와 스크립트 모드 모두 같은 명령 경계로 직구와 스윙을 실행한다.
- 접촉 타이밍과 각도를 바꾸면 타구 속도·방향이 명시한 단순 모델에 따라 달라진다.
- 단일 주자가 베이스 경로를 이동하고 목표·도착 상태를 조회할 수 있다.
- 최소 수비가 이동, 뜬공/땅볼 포구, 1루 송구와 소유권 이전을 수행한다.
- `Miss`, `Foul`, `FlyOut`, `SafeAtFirst`, `ForceOutAtFirst`, `RunScored`, `OutOfPlay`, `DeadBall`, `Timeout` 중 해당 결과 하나만 확정된다.
- 상태, 공 속도, 소유자, 주자, 결과, 타이머를 화면에서 확인할 수 있다.
- 플레이 도중과 종료 후 초기화가 모든 물리·논리 상태를 복원하며 여러 번 반복해도 잔존 상태가 없다.
- 주요 조건과 시드를 바꿔 다시 실행할 수 있고 실행 조건을 기록한다.
- `docs/verification.md`의 필수 시나리오를 실제로 실행해 결과를 기록한다.
- 완료 조건에 학습 성능, 보상 조정, ML-Agents 연결은 포함하지 않는다.
