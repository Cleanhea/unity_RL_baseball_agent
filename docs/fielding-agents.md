# 수비·주루 Agent와 플레이 판정 (3단계)

2026-09-26 요청으로 3단계(타자·주자 + 투수 + 수비 5명) 학습을 위해 수비 이동·포구·송구·아웃 판정과 두 Agent를 추가했다. 같은 날 후속 요청으로 **주자 여러 명**(타자주자 + 1·2·3루 누상 주자)과 볼카운트·이닝 상황을 더했다([상황 규칙](game-situation.md)).

- 수비는 **1루수·유격수·3루수·좌중간·우중간 외야수 5명**이다. 포수·2루수는 없다.
- 달리기는 환경이 제공하고, 주자 Agent는 진루/귀루 판단만 한다.
- 규칙은 `PlayDirector`가 판정하며 결과의 단일 소유자다.
- 수비수·누상 주자가 없는 씬(`BaseballPlayground`, 1·2단계)에서는 새 규칙이 동작하지 않아 기존 동작과 같다. 기존 검증 5종으로 확인했다.

## 수비·주루 규칙 (환경)

| 항목 | 규칙 | 설정(`BaseballEnvironmentConfig` › 수비) |
| --- | --- | --- |
| 이동 | 명령(필드 XZ 방향, 크기 1 = 최고 속력)을 가속도 한도 안에서 따른다. 경기 경계 1 m 안쪽에 머문다 | `Fielder Speed` 7.5 m/s, `Fielder Acceleration` 15 m/s² |
| 포구 | 이번 고정 단계의 공 경로가 수비수 몸 축에서 수평 반경 안, 지면~최고 높이 사이를 지나면 자동으로 잡는다. 여럿이면 경로상 먼저 닿는 수비수다. 방금 던진 수비수는 0.3 s 동안 다시 잡지 않는다 | `Catch Radius` 1.0 m, `Catch Reach Height` 2.4 m |
| 뜬공 아웃 | 타구가 땅·펜스에 닿기 전에 잡으면 타자 아웃(파울 지역 포함). 모든 포스가 풀린다. 베이스를 벗어났던 누상 주자는 시작 베이스로 자동으로 돌아가 리터치해야 한다 | |
| 페어/파울 | 판정 전 땅볼을 잡으면 잡은 지점의 지역으로 정한다. 파울이면 `Foul`로 끝난다. 수비수가 한 번 닿은 뒤에는 페어/파울·홈런 판정을 하지 않는다 | |
| 송구 | 공을 가진 수비수가 1루·2루·3루·홈 중 하나를 고르면 그 베이스 위 글러브 높이(1.2 m)로 회전 없이 던진다. 실제 비행과 같은 적분으로 조준하며, 닿지 못하는 거리면 거부한다 | `Throw Speed` 30 m/s |
| 포스 | 타자주자와, 뒤 베이스가 모두 찬 누상 주자는 타구 순간 다음 베이스로 자동으로 달린다. 공을 가진 수비수가 아직 도착하지 않은 포스 베이스(홈 포함) 반경 안이면 아웃. 뒤 주자가 아웃되면 앞 주자의 포스가 풀린다 | `Base Cover Radius` 0.6 m |
| 태그 아웃 | 진루·귀루 중인(베이스에 멈추지 않은) 주자와 공을 가진 수비수의 거리가 반경 안이면 아웃 | `Tag Radius` 0.8 m |
| 리터치 | 리터치 전에 공을 가진 수비수가 그 주자의 시작 베이스를 밟으면 아웃(태그 아웃으로 기록). 리터치 뒤에는 태그업 진루할 수 있다 | |
| 플레이 종료 | ① 세 번째 아웃 ② 살아 있는 주자 없음(모두 득점·아웃) ③ 살아 있는 주자가 모두 베이스에 멈추고 리터치할 주자가 없으며 수비가 공을 가진 상태가 이어짐 → `RunnerSafe`. 득점·홈런·인정 2루타·파울·12 s 시간 초과는 기존 규칙 | `Play Dead Seconds` 1.0 s |

③의 지속 시간은 공을 잡은 순간 플레이가 죽지 않게 하려는 것이다. 그래야 태그업·추가 진루를 시도할 수 있다. 처음에는 즉시 종료였는데, 희생플라이 검증에서 주자가 태그업할 수 없는 문제로 드러나 고쳤다.

새 명령은 모두 고정 단계에서 적용한다.

- `RequestFielderMove(index, Vector2)`: 이동. 다음 명령까지 유지한다.
- `RequestFielderThrow(index, ThrowTarget)`: 송구. 한 번만 처리한다.
- `RequestRunnerDecision(slot, RunnerDecision)`: 슬롯 0 = 타자주자, 1~3 = 누상 주자.
- `RequestSetSituation(1루, 2루, 3루, 아웃)`
- `RequestScriptedBattedBall(Vector3)`: 검증·시나리오용. 투구 없이 타석 앞에서 타구를 시작한다.

새 조회와 이벤트는 다음과 같다.

- `BallHolder`, `BattedBallFielded`, `GetFielder(i)`
- `GetRunnerSnapshot(slot)`, `IsRunnerForced(slot)`, `RunnerNeedsRetouch(slot)`
- `GetSituation()`, `TryGetPlaySummary()`
- 이벤트: `BallFielded(수비수, 공중 포구 여부)`, `PlayResolved(요약)`

`PitchEndReason`에 `FlyOut`, `ForceOut`, `TagOut`, `RunnerSafe`를, `RunnerPhase`에 `Out`을 더했다. 여러 아웃이 난 플레이의 종료 사유는 마지막 아웃의 종류다. 결과 판단은 종료 사유가 아니라 `PlaySummary`로 한다.

## 수비수 Agent `BaseballFielder`

다섯 명이 같은 Behavior를 쓰고(팀 1), 역할은 관측의 원-핫으로 구분한다. `TrainingEnvController`가 `SimpleMultiAgentGroup`으로 묶어 팀 보상을 주므로 MA-POCA로 학습한다. 타구가 살아 있는 동안만 5 고정 단계(0.1 s)마다 결정하고, 사이 단계는 마지막 행동을 반복한다. 공에 닿지 않은 투구(볼·스트라이크)에서는 결정도 에피소드도 없다.

**관측 65개:**

| 항목 | 수 |
| --- | --- |
| 역할 원-핫(1B, SS, 3B, LCF, RCF) | 5 |
| 자기 위치 x/z (홈 기준) | 2 |
| 자기 속도 x/z | 2 |
| 공 소유: 자기·동료·없음 | 3 |
| 공의 상대 위치 x, 높이(지면 기준), z | 3 |
| 공 속도 | 3 |
| 타구가 땅에 닿았거나 이미 수비됨 | 1 |
| 타구 플레이 중 | 1 |
| 아웃 수 / 2 | 1 |
| 주자 슬롯 4개 × (살아 있음, 상대 x·z, 진루 중, 귀루 중, 포스, 리터치 필요) | 28 |
| 1·2·3루·홈의 상대 위치 | 8 |
| 동료 4명의 상대 위치 | 8 |

위치는 60 m, 공 속도는 40 m/s, 자기 속도는 최고 속력으로 나눈다. 2026-09-27부터 모든 위치는 자기 경기장의 홈 기준이다(자기 위치, 공 높이 포함). 그래서 경기장을 복제하거나 옮겨도 같은 상황은 같은 관측이 된다. 수비·주자 관측은 게임 상태를 그대로 읽는다. 타자처럼 레이로 "보게" 하지 않았다.

**행동:**

- 연속 2개: 이동 방향·세기 (필드 x, z)
- 이산 `[5]`: 0 송구 안 함, 1 1루, 2 2루, 3 3루, 4 홈. 공을 가진 수비수만 적용된다

`Heuristic`은 중립 행동(제자리, 송구 없음)이다.

## 주자 Agent `BaseballRunner`

주자 슬롯 네 명이 같은 Behavior를 쓴다(팀 0).

- 슬롯 0: 기존 타자주자 `BatterRunner`
- 슬롯 1~3: 새 누상 주자 `BaseRunner_1B/2B/3B`. 새 타석마다 점유된 베이스에 선다

타구 순간 살아 있는 주자만 이번 플레이의 **주자 그룹**(`SimpleMultiAgentGroup`, MA-POCA)에 들어간다. 살아 있는 동안 5 고정 단계마다 결정한다.

**관측 57개:**

| 항목 | 수 |
| --- | --- |
| 슬롯 원-핫 | 4 |
| 상태 원-핫(진루·귀루·멈춤) | 3 |
| 마지막으로 밟은 베이스 원-핫 | 4 |
| 향하는 베이스 원-핫 | 4 |
| 멈출 목표 베이스 원-핫 | 4 |
| 포스 | 1 |
| 리터치 필요 | 1 |
| 위치 x/z (홈 기준) | 2 |
| 다음 베이스까지 거리 | 1 |
| 공 위치 (홈 기준) | 3 |
| 공 속도 | 3 |
| 공이 잡혔는지 | 1 |
| 공을 가진 수비수의 상대 위치 | 2 |
| 타구가 땅에 닿았는지 | 1 |
| 아웃 수 / 2 | 1 |
| 다른 주자 3명 × (살아 있음, 상대 x·z, 향하는 베이스) | 12 |
| 수비 5명의 상대 위치 | 10 |

**행동:** 이산 `[3]`. 0 판단 없음, 1 진루, 2 귀루. `RequestRunnerDecision(slot, …)`을 쓴다. `Heuristic`은 판단 없음이다. 포스된 베이스까지만 자동으로 달리고 멈춘다.

## 결과 보상

플레이가 끝나면 `PlaySummary`로 계산해 한 번 준다. 자세한 식과 예시는 [상황 규칙](game-situation.md)에 있다.

| 대상 | 규칙 |
| --- | --- |
| 수비 그룹 | 아웃마다 `+1`, 내준 베이스마다 `-0.25`, 득점마다 `-1`. 타구가 살아 있는 고정 단계마다 `-0.0005` |
| 주자 그룹 | 전진한 베이스마다 `+0.25`, 득점마다 `+1`, 베이스 위 아웃(포스·태그·리터치 전 태그)마다 `-1`. 타자의 뜬공 아웃은 주자 책임이 아니다 |
| 타자·투수 | 타석이 끝날 때 결과 보상. 타자는 얻은 베이스·타점마다 `+0.5`, 그 플레이의 아웃마다 `-0.5`. 투수는 반대 부호 |

## 검증 시나리오

`Verify Open Training Scene`을 `Stage3_FullTeam`에서 실행한다.

- 모든 Agent는 중립 행동이고 무작위 상황은 끈다.
- 각 시나리오는 `RequestSetSituation`으로 누상 주자·아웃을 정한 뒤 시나리오 타구로 시작한다.
- 수비·주루는 같은 명령 경계로 덮어쓰는 단순 스크립트다.

**스크립트 수비의 동작**

- 공을 가진 수비수: 아직 도착하지 않은 가장 앞선 포스 베이스가 12 m 안이면 직접 밟고, 멀면 그 베이스로 던진다. 포스가 없으면 리터치할 주자의 원래 베이스로, 그것도 없으면 달리는 주자가 향하는 베이스로 던진다.
- 공이 살아 있으면 예상 지점에 가장 가까운 수비수가 쫓는다.
- 커버: 1루수는 1루. 유격수는 주자가 2루로 갈 때나 1루 주자가 포스일 때 2루. 3루수는 주자가 3루로 갈 때나 2루 주자가 포스일 때 3루.

| 시나리오 | 상황 | 기대 결과 |
| --- | --- | --- |
| 중립 투구 | — | 존 중앙 3개 삼진, 수비 에피소드 없음 |
| A 유격수 땅볼 | 주자 없음 | 1루 `ForceOut` |
| B 좌중간 뜬공 | 주자 없음 | `FlyOut` |
| C 가운데 안타 | 주자 없음 | 1루 `RunnerSafe`, 다음 타석 1루 주자 |
| D 같은 안타에 2루 시도 | 주자 없음 | 타이밍에 따라 `TagOut` 또는 2루 세이프 |
| E 3루 쪽 파울 뜬공 | 주자 없음 | 파울 지역 `FlyOut` |
| F 유격수 땅볼 | 1루 | 2루 포스(+1루 송구). 병살 또는 한 개 아웃 + 타자 1루 |
